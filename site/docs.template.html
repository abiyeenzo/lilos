Démarrage rapide

Dépendances : nasm, gcc avec le support 32 bits (gcc-multilib), binutils, qemu-system-x86, python3, openssl.

git clone https://github.com/abiyeenzo/lilos
cd lilos
make            # construit build/lilos.img
make run        # lance dans QEMU, réseau RTL8139 inclus

Au premier démarrage, LilOS demande le mot de passe de root, puis crée un compte utilisateur. Les comptes et les fichiers vivent en RAM : tout est recréé à chaque démarrage. Il faut au moins 32 Mo de RAM.

Essayez :

aide
ecrire notes.txt café à côté
afficher notes.txt
calculer 6 * 7
lancer bonjour

Commandes

Les noms sont en français. Les anciens noms anglais sont toujours acceptés comme alias. aide <commande> donne le détail dans LilOS. Les commandes marquées root sont réservées à l'administrateur.

@@COMMANDES@@
CommandeAliasDescription

Raccourcis : flèches haut et bas pour l'historique, Ctrl+L pour effacer l'écran, Ctrl+C pour interrompre un programme.

Comptes et droits

Chaque session a un utilisateur. root (uid 0) peut tout faire. Les autres comptes ne peuvent ni lire la mémoire du noyau, ni créer de comptes, ni éteindre la machine.

Chaque fichier a un propriétaire et des droits pour lui et pour les autres : 4 pour la lecture, 2 pour l'écriture. droits notes.txt 64 donne lecture et écriture au propriétaire et lecture aux autres (le réglage par défaut). droits notes.txt 60 interdit tout aux autres.

Les mots de passe ne sont jamais stockés : on garde un sel aléatoire et un SHA-256 itéré. Après un échec de connexion, une temporisation freine le force brut.

Programmes utilisateur

Les programmes tournent en ring 3, dans leur propre espace d'adressage (0x40000000 à 0x40100000). Ils parlent au noyau par int 0x80 : écrire, lire une ligne, lire et écrire un fichier (avec les droits de l'utilisateur), dormir, obtenir son uid.

programmes les liste, lancer <nom> [arguments] en exécute un. Quelques exemples :

lancer moi un deux      # uid, pid et arguments
lancer noter a.txt salut
lancer lire a.txt
lancer noyau            # tente de lire le noyau : le processus est tué
lancer boucle           # boucle infinie : Ctrl+C l'arrête

Pour écrire le vôtre : copiez user/bonjour.c, ajoutez le nom à USER_PROGS dans le Makefile et à kernel/programs.c. Voir le guide de contribution.

Réseau

LilOS pilote la carte RTL8139 (celle que QEMU émule avec -nic user,model=rtl8139) et parle ARP, IPv4, ICMP, UDP et DNS. Il n'y a pas encore de TCP.

reseau            # état de la carte, MAC, adresse
ping 10.0.2.2     # la passerelle de QEMU
dns example.com   # résolution de nom
arp               # cache ARP

L'adresse par défaut est celle du réseau utilisateur de QEMU (10.0.2.15, passerelle 10.0.2.2, DNS 10.0.2.3). Root peut la changer avec reseau config <ip> <passerelle> <dns>.

Architecture

Adresse physiqueContenu
0x7C00secteur de boot
0x10000noyau (code, données, BSS)
0x90000sommet de la pile du noyau
0x100000 - 0x1000000heap du noyau
0x1000000 - 0x2000000pages des processus

Les processus voient leur propre fenêtre à 0x40000000. Le noyau n'y est jamais accessible.

tests/tests hôte, fuzzers, tests QEMU et tests d'attaque
site/ce site

Sécurité

Le modèle de menace, les protections et les limites connues sont décrits dans SECURITY.md. En résumé : isolation des processus, W^X, NX, SMEP, ports d'E/S interdits au ring 3, heap vérifié, pile gardée, pile réseau défensive, comptes salés.

Le dépôt est attaqué en continu par ses propres tests. Ils ont déjà trouvé de vraies failles, par exemple l'accès aux ports matériels depuis un processus non privilégié, qui permettait d'espionner le clavier. Pour signaler une faille, utilisez le signalement privé.

Vérifier une release

Chaque release contient l'image, sa signature Ed25519, les empreintes SHA-256 et la clé publique. La clé privée n'existe que dans un environnement GitHub protégé.

sha256sum -c SHA256SUMS
openssl pkeyutl -verify -pubin -inkey lilos-release.pub.pem \
  -rawin -in lilos.img -sigfile lilos.img.sig
gh attestation verify lilos.img --repo abiyeenzo/lilos

La première commande vérifie l'intégrité, la deuxième que le projet a bien signé l'image, la troisième qu'elle a été construite par le dépôt (provenance).

Tests

make test-heap test-lib test-fs test-sha test-net   # tests hôte, ASan et UBSan
make test                                           # QEMU : clavier, comptes, ring 3, réseau
make test-attack                                    # 51 attaques depuis le mode utilisateur
make test-netattack                                 # paquets hostiles envoyés à la VM
make fuzz-shell SEED=1 ROUNDS=100                   # touches aléatoires dans le shell

Les tests QEMU tapent de vraies touches AZERTY et lisent la sortie série. La CI lance tout à chaque push.
